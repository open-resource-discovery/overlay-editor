## Project Overview

`@open-resource-discovery/overlay-editor` is a **dual-purpose repository**:

1. **A publishable React component library** (`src/lib/`) built with **Vite** in
   library mode. It ships `OverlayCardView` — a read-only component that renders
   an ORD Overlay 0.1 document (overview, target, and a searchable patch list with
   syntax-highlighted payloads) — plus the backing Zustand stores, a theme hook,
   and the overlay types. Built to `dist/` (ESM + bundled `.d.ts` + a single
   `dist/index.css`).

2. **A documentation + playground site** (`website/`) built with **Docusaurus**
   (classic preset). It consumes the library via a `file:..` dependency and
   provides a home page, a 3-pane interactive playground (example selector +
   Monaco JSON editor + live `OverlayCardView`), and minimal docs.

An **ORD Overlay** is a JSON/YAML document (`ordOverlay: "0.1"`) describing
patches (`update` / `merge` / `remove`) to apply to an API or metadata
definition (OpenAPI, EDMX/OData, CSN Interop, MCP server card, A2A agent card)
via concept-level selectors — without editing the original.

**All code is TypeScript.** No `.js` source except configs that require it.

## Commands

```bash
# Library
npm run build:lib        # Vite lib build → dist/ (ESM + types + CSS)
npm run build            # Alias of build:lib (website prestart/prebuild call this)
npm run typecheck        # tsc --noEmit over src/ + tests/
npm run test             # Vitest unit tests (run once)
npm run test:watch       # Vitest watch mode
npm run lint             # ESLint (typescript-eslint flat config, src/ + tests/)
npm run check            # typecheck + lint + test
npm run format           # Prettier + ESLint auto-fix

# Website
npm run website:start    # Rebuilds the lib, then runs Docusaurus dev server
npm run website:build    # Rebuilds the lib, then builds the static site → website/build
```

> The website's `prestart`/`prebuild` run `npm --prefix .. run build`, so the
> `dist/` the site consumes is always fresh. When iterating on `src/lib`, re-run
> the library build (or `website:start`) to pick up changes.

## Architecture notes

- **Library consumption in Docusaurus**: `OverlayCardView` is ESM-only, renders
  under `"use client"`, and injects its CSS at runtime — so `website/src/components/Playground/renderer.tsx`
  loads it via `React.lazy(() => import(...))` inside `<BrowserOnly>` + `<ErrorBoundary>`.
  Do NOT import the library statically in the SSR/SSG graph.
- **Theming**: the library self-themes under `.ord-ui` and reads its own theme
  store. The site syncs Docusaurus color mode into it (`useThemeStore.getState().setTheme(colorMode)`
  in `renderer.tsx`) and wraps chrome in `.ord-ui`/`.dark`.
- **Tailwind in the site**: wired through a PostCSS plugin in `docusaurus.config.ts`.
  Utilities are imported **unlayered** in `custom.css` (skipping preflight) so
  class specificity wins over Infima without needing CSS cascade layers.
- **Data**: static files under `website/static/`; URLs are joined with the site
  base URL via `useBaseUrlUtils().withBaseUrl` (no build-time env prefixing).
- **`@/` alias** → repo root (library/tests). The website uses Docusaurus'
  `@site/*` alias.

## Quality gates

Run `npm run check` after changes to the library. For site changes, also run
`npm run website:build` (it triggers a library rebuild) and watch for broken
links (`onBrokenLinks: 'throw'`).

## Deployment

GitHub Pages deploys `website/build`. The Pages/PR-preview workflows build the
library, then the site with `BASE_URL` set (`/overlay-editor/` for production,
`/pr-preview/overlay-editor/pr-<n>/` for previews).
